# RoboCop for Police Chief Simulator

Author: Joe "Gambit" Bradford

This is the source for installer 1.0.0-RC4, gameplay Lua v0.4.3 and the native
helper v0.4 used by that Lua. The native source version did not change when the
30-second timer was added to Lua. The binary model and portrait packages are
separate cooked assets, not generated by the C helper.

## Code map

| File | Responsibility |
| --- | --- |
| `Install_RoboCop.bat` | Readable Windows entry point; invokes the bundled PowerShell |
| `Installer/Install.ps1` | Game selection, console output and logging |
| `Installer/Core.ps1` | Hashing, backups, installation and rollback |
| `Installer/Discovery.ps1` | Executable resolution and Steam discovery |
| `Installer/Runtime.ps1` | Official experimental update selection, download and content staging |
| `Installer/manifest.json` | Exact payload hashes, supported game hash and UE4SS provenance |
| `Payload/RoboCopGameplay/Scripts/main.lua` | Worker identity, name/stats, GUID handoff and patrol timer |
| `Source/Native/robocop.c` | Native salary, death and patrol-result hooks |
| `Source/Native/build_manifest.h` | Supported executable signature and function-byte guards |
| `Source/Tools/build_release.py` | Assemble a release from source and the pinned asset packages |
| `Source/Tests/` | Installer and timer regression tests |

The native helper changes process memory at runtime after checking the game build.
It does not patch the game executable on disk. It is pinned for the lifetime of
the process, which is why full restarts are required. All four hook functions and
their installation/guard/rollback implementation are in the included C source.
The installer obtains experimental-release metadata from the official GitHub API
and downloads a newer official runtime ZIP when needed. It verifies the archive
digest and installs only the required runtime files; it does not execute downloaded
scripts or start the game. The game loads the installed DLLs on its next launch.

## Build

1. Install Zig 0.16.0 and Python 3.11 or newer on the build machine.
2. From an extracted source tree, run `Source/Native/build_native.bat` on Windows.
   The equivalent cross-compile command from the repository root is:

   ```text
   zig cc -target x86_64-windows-gnu -shared -O2 Source/Native/robocop.c -o Payload/RoboCopGameplay/robocop_native.dll
   ```

3. Obtain the author's `RoboCop_Worker02_v0.3_6ft4_TEST.zip` and
   `RoboCop_Portrait_v1_TEST.zip` asset packages. They contain the cooked model,
   materials and portrait. This source-only archive intentionally excludes them.
4. Obtain the pinned upstream runtime:
   https://github.com/UE4SS-RE/RE-UE4SS/releases/download/experimental/UE4SS_v3.0.1-1136-g35d1795d.zip
5. Assemble the release:

   ```text
   python Source/Tools/build_release.py --model RoboCop_Worker02_v0.3_6ft4_TEST.zip --portrait RoboCop_Portrait_v1_TEST.zip --ue4ss UE4SS_v3.0.1-1136-g35d1795d.zip --output RoboCop_Installer.zip
   ```

The builder verifies the supplied assets against the release manifest and records
the compiled DLL's new hash. Existing Lua edits require an intentional manifest
update. It never includes the game executable, saves, private logs or credentials.

## Tests

Run `powershell -NoProfile -File Source/Tests/test_installer.ps1` on Windows, or
`pwsh -NoProfile -File Source/Tests/test_installer.ps1` on Linux. Fixtures use
temporary fake game/payload files; they do not touch an installed game.
The timer test requires Python's `lupa` package:
`python Source/Tests/test_patrol.py`.

The automated file-operation tests are not a substitute for a Windows 5.1
double-click test or a real-game test of fresh UE4SS initialization.

## GitHub / Nexus

Upload the contents of the separate source ZIP as the root of a public GitHub
repository. Keep the directory layout intact. Share that repository's actual URL
with Nexus and link it on the mod page. This package does not create or publish a
repository, and no GitHub URL is claimed until the source has been uploaded.

Publish the installer ZIP as the player download, not the source ZIP. Publish
updated source whenever executable code changes. The source archive includes the
mod's Lua, native C/header, batch and PowerShell scripts plus tests and packaging
code. It does not include third-party 3D authoring assets or Unreal Engine source.

## Third-party components

UE4SS: https://github.com/UE4SS-RE/RE-UE4SS/tree/35d1795d

in `Installer/manifest.json`. The upstream MIT license accompanies the runtime.

when their hashes differ; existing settings and other mods are preserved.

## RC4 installer update

RC3 found the game correctly on the reported PC but rejected its OneDrive Desktop
because every package file's ancestors were checked for any reparse point. RC4
removes that check for read-only package sources. All required source contents
are SHA-256 verified and copied through streams to a temporary staging directory.
This permits cloud-backed or linked source directories without copying their link
attributes into the installed game. Installation-target checks remain active.

The destination layout is always:

- `PoliceChiefSimulator/Content/Paks/~mods/` for the six cooked assets.
- `PoliceChiefSimulator/Binaries/Win64/ue4ss/Mods/RoboCopGameplay/` for the mod.
- `PoliceChiefSimulator/Binaries/Win64/ue4ss/UE4SS.dll` for the runtime.
- `PoliceChiefSimulator/Binaries/Win64/dwmapi.dll` for its loader.

The installer checks the official experimental release API for the newest basic
ZIP. Only exact official download URLs and SHA-256 digests are accepted. It uses
the bundled archive contents when those match the release; otherwise it downloads
and verifies the selected archive, then extracts four explicitly named files.
An unreachable API produces an explicit bundled-build fallback message. Unexpected
metadata or a failed download verification stops before modifications.

Existing DLLs are compared to the selected runtime by content hash, independently
of settings. Missing and differing DLLs are installed, with backups and rollback.
Existing settings and other mods are preserved. Legacy mods and supported override
files are copied into the nested layout without replacing existing nested copies.
The flat UE4SS.dll is backed up and removed to leave one active runtime. Legacy
files remain available as inactive copies. Custom directory overrides, explicit
RoboCop disable entries and conflicting legacy/nested load lists still stop.

Run `Source/Tests/test_discovery.ps1`, `Source/Tests/test_runtime.ps1` and
`Source/Tests/test_installer.ps1`. The synthetic tests create temporary fixtures
and mock network responses; they do not change an installed game. The linked-source
case first reproduces RC3's old rejection, then verifies RC4 installs ordinary
files from that same source. Runtime tests exercise selection, download, extraction,
integrity failures, allowed URLs and the explicit offline fallback.

The optional `Source/Tests/test_release.ps1 -GameExe <path>` uses the actual release
payload and a COPY of the supplied game executable, without launching it. It tests
fresh installation, matching-runtime retention and replacement of an outdated
runtime while preserving another mod, settings and the load list.

`.github/workflows/installer-tests.yml` runs synthetic tests on Windows PowerShell
5.1 and PowerShell 7 after GitHub publication. That workflow has not run here.
Local validation used Linux PowerShell 7.4.13. Live official archive retrieval and
integrity checks also passed. Windows UI, OneDrive hydration, double-click startup
and real-game behavior of the new experimental runtime remain unverified here.
